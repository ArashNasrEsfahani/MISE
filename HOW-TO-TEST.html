0a · The one-click way in verified

Everything below can be done by hand, and the manual commands are given so you always know what is happening. But there is a launcher that does the tedious parts for you — double-click START-TESTING.bat in the project root.

It gives you a menu:

  • [1] Start everything — preflights Ollama, re-derives the WSL → Windows IP, repairs sim/gui_config.json if it drifted, starts the console inside WSL with the GPU env vars, waits for the port, then opens the console, the trace viewer and this guide. That is Track C mission C1 done for you.
  • [2] Offline checks — runs all six self-test suites. Roughly Track A in one keypress.
  • [4] Stop everything — shuts the console down and frees the GPU. Use this before any simulator benchmark (see Rule 3).
  • [5] Diagnose — prints what is up and what is not, which is the fastest first move when something misbehaves.
Two things the launcher knows that are easy to get wrong

Use 127.0.0.1, never localhost, when checking Ollama from Windows. PowerShell resolves localhost to ::1 first and Ollama binds IPv4 only, so the localhost form times out rather than failing fast — which looks exactly like "Ollama is down" when it is perfectly healthy.

An open port 8000 does not mean your console is there. The launcher probes /status and distinguishes "our console" from "some other process squatting on the port" — a stale web server on 8000 will otherwise give you a dead browser tab and a confusing hunt.

Rule 1 — run from the repo root, never from sim/ verified

sim/trace.py shadows Python's own stdlib trace module. From the repo root the stdlib wins and nothing breaks. From inside sim/ the project module wins, and any third-party code that expects the stdlib trace gets the project's instead.

the root cause — it is not the database

sim/trace.db lives beside the code, which under WSL means /mnt/d — a Windows drive over DrvFs. SQLite's WAL mode needs a shared-memory index file (-shm) backed by working mmap and POSIX advisory locks, and DrvFs provides neither reliably.

It does not fail cleanly. The store opens, accepts writes for a while, and then every read and write starts returning unable to open database file — with the file already structurally corrupt. Measured on the second occurrence, minutes after a completely clean rebuild:

The tell that cracked it: Windows-side Python could read the very file that WSL-side Python could not open. That points at the -shm layer, not at the database.

trace.py:_wal_is_safe now picks the journal mode from the filesystem — WAL on a real Linux path or on native Windows, a rollback journal on a WSL-mounted Windows drive. Gated by T-73…T-77 in sim/_trace_selftest.py.

                        retrieval grounding for the planner prompt: off |
                        keyword (HybridRAG alpha=1.0) | hybrid (alpha=0.5,
                        needs embeddings) | probe (chunkless lexical, 0 extra
                        model calls) | agentic (probe + a bounded multi-hop
                        object-type pivot) | full (dump the whole in-scope KB
                        -- the no-retrieval control)
  --rank {plain,provenance,provenance+utility}
                        ranking function for probe/agentic (plain = similarity
                        only, the control arm). 'provenance+utility'
                        additionally writes retrieval credit via rag.credit
                        and reads it back through rank_key's utility term --
                        it needs --loop on to differ from 'provenance',
                        because the credit write is an outcome-derived write
                        and a frozen pass stays frozen
  --agentic-hops {0,1,2,3}
                        hop budget for extra LLM retrieval hops (0 = probe-
                        only); ignored by --rag probe. The LEVEL POLICY scales
                        it (L1 x0, L2 x0.5, L3 x1), so at the default
                        --agentic-level est this is the L3 budget and L1
                        always gets 0
  --agentic-pivot {off,lex,llm,auto}
                        query decomposition into AI2-THOR object types (the
                        FA->EN bridge); auto spends a model call only when a
                        Persian command resolved no types lexically
  --agentic-gate {on,off}
                        deterministic sufficiency gate (off = always spend the
                        full hop budget)
  --agentic-cache {on,off}
                        exact-match probe cache keyed on the KB content hash;
                        turn OFF for timing runs
  --agentic-compact {on,off}
                        merge near-duplicate lessons and truncate the memory
                        block to the budget

                        genuinely separate axis from --rag: the repair fires
                        on EVERY retrieval arm, --rag off included
